# FEYNLAG_GAPS.md

Things `feynlag` (pinned commit in `pyproject.toml`) cannot do that a model in
this repository needed. Each entry names the model item that was **stopped**
(not worked around). Append-only; ids are referenced from the `feynlag_gaps` key of each
`metadata.yaml`. Rows stay after a fix; a fixed gap is recorded under
**Resolved** and removed from every `metadata.yaml`.

| id | model / item | what was attempted | what feynlag lacks | evidence |
|---|---|---|---|---|
| FG-1 | `sm_singlet_z2` / CP-even, CP-odd and charged scalar mass blocks | `Model.mass_matrix([h, S])` with `S = Scalar(real=True)` + `expand_vev({S: vS})` | `scalar_mass_matrix`/`charged_mass_matrix` shift the potential, differentiate, then call `Vacuum.at_vacuum`, which shifts **again**; for a real field the fluctuation symbol is the component itself, so every block is evaluated at $S = 2v_S$ ($M_{11} = 2\lambda v^2 + \tfrac32\lambda_{HS}v_S^2$ instead of $2\lambda v^2$, $M_{22} = 11\lambda_S v_S^2$ instead of $2\lambda_S v_S^2$; the would-be Goldstone blocks pick up $\lambda_{HS}v_S^2$ pieces). Tadpoles (single `at_vacuum`) and `physical_lagrangian` (single `shift`) are unaffected. | `models/sm_singlet_z2/tests/test_l0_l1.py::test_feynlag_mass_matrix_real_scalar_gap` (strict xfail: flips when fixed). Workaround kept *outside* feynlag: `feynlag_models.checks.scalar_mass_block` (public `build_mass_matrix` + one explicit vacuum evaluation). |
| FG-2 | `sm_singlet_z2` / L0 discrete invariance of the full Lagrangian | `Model(discrete_groups=[Z2]).check_invariance()` with `Z2.assign(1, S)` | `check_discrete_invariance` reports a violation on the `Dmu`-built Higgs kinetic term although `Z2` does not act on `H` at all (also fails with `H` explicitly assigned even; the residual is a momentum-tag artefact `p(Gp) − p(conjugate(Gp))`). Potential and Yukawa terms are checked correctly. feynlag's own `examples/thdm.py` never declares its `Z2` on the `Model`, so this path is untested upstream. | `models/sm_singlet_z2/tests/test_l0_l1.py::test_feynlag_discrete_kinetic_gap` (strict xfail). L0 is claimed on: gauge invariance + hermiticity + dimension of every term, anomalies, and `Z2` invariance of every non-`Dmu` term, with the kinetic false positive being the *only* failure (`only_failures`). |
| FG-3 | `seesaw_type1` / L3 UFO export | Export the heavy-neutrino vertices ($W\ell N$, $Z\nu N$, $h\nu N$) obtained through `MajoranaRotation` | No UFO path for Majorana fermions: `write_ufo(fermion_vertices=…)` takes Dirac `bar`/`field` pairs and feynlag's `CLAUDE.md` lists "UFO export of Majorana vertices" as v2-deferred (fermion-flow conventions for self-conjugate fields are not implemented). The bosonic + charged-fermion part of the model could be exported, but that would not be *this* model's UFO. Item stopped; `maturity_level: 2`. | `models/seesaw_type1/model.py` (`extra["ufo"] = False`; `outputs()` writes no UFO). |
| FG-4 | `sm_ckm` / L1 quark and lepton mass matrices | `fermion_mass_matrix(L, QLbar, uR, vacuum, 3, (i, j), gamma=diracPR)` on a three-generation Yukawa written with integer flavour indices (`Bilinear(QLbar[0], PR, uR[2])`, …) | The function renames each term's indices to the symbolic `(i, j)` with `c.subs({term_idx[0]: i, term_idx[1]: j})`. For integer indices this substitutes the *numbers* 0, 1, 2 inside the coefficient and, since the indices no longer sit in the term, every flavour pair lands in every entry: the diagonal up Yukawa returns a full matrix with entries such as $m_c + m_u + m_t/\sqrt2$. `majorana_mass_matrix` has the same `subs` line. Only symbolic flavour indices (one generation, as in every other model) are safe. | `models/sm_ckm/tests/test_l0_l1.py::test_feynlag_fermion_mass_matrix_integer_flavour_gap` (strict xfail). Workaround kept *outside* feynlag: `feynlag_models.checks.fermion_mass_block` reads each term at its own integer indices (`test_fermion_masses`). |
| FG-5 | `seesaw_type1_2n` / L1 Takagi factorisation of the $5\times5$ seesaw matrix | `diagonalize_takagi(M)` on the benchmark $M_\nu$ (exact rationals and $\sqrt2$; generic real $3\times2$ $m_D$, $M_R = \mathrm{diag}(M_1, M_2)$) | `diagonalize_takagi` calls SymPy's symbolic `Matrix.diagonalize`; the characteristic polynomial is $\lambda\times$(a quartic) and the call did not finish in 120 s. The module docstring already says "never rely on symbolic `eigenvects` for >2×2" and points to numeric diagonalisation, but feynlag has no numeric Takagi. Its $6\times6$ test passes only because a diagonal $m_D$ splits the matrix into $2\times2$ blocks. | `models/seesaw_type1_2n/tests/test_l0_l1.py::test_feynlag_takagi_generic_matrix_gap` (strict xfail, 10 s timeout). Workaround kept *outside* feynlag: `feynlag_models.checks.numeric_takagi` (mpmath `eigsy` at 50 digits, same phase convention), whose output feeds feynlag's `MajoranaRotation` unchanged. |

| FG-5 | [`e34b356`](https://github.com/moiseszeleny/feynlag/commit/e34b356) ([PR #25](https://github.com/moiseszeleny/feynlag/pull/25), squash-merged) | `diagonalize_takagi` had only the exact route (`Matrix.diagonalize`), which cannot solve the $\lambda\times$quartic characteristic polynomial of a generic $5\times5$. The benchmark $5\times5$ now takes 0.015 s, and its $U$ agrees with the old workaround to $2\times10^{-38}$. | feynlag `tests/test_seesaw.py::TestNumericTakagi` (generic $5\times5$ within 10 s, reconstruction and unitarity to $10^{-40}$, agreement with the exact route on the block $6\times6$); here `seesaw_type1_2n` builds `U`, `D` with `diagonalize_takagi` (`test_takagi_spectrum_at_benchmark`, `test_light_sector_rank_two`, all of L2). `feynlag_models.checks.numeric_takagi` and `tests/test_checks.py` removed. |
